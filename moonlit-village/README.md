# 月下疑云 / Moonlit Village

### 音效延迟修复（2026-10-30）

以前每种音效首次触发时才通过 `new Audio(path)` 建立播放器，并在后续每次触发时执行 `pause() → currentTime=0 → play()`，在移动 Safari 上容易出现明显的解码或音频管线启动延迟。

现在页面加载时通过 `fetch() + AudioContext.decodeAudioData()` 预取、解码六个音效，常规点击直接用 `AudioBufferSourceNode.start(0)` 播放。首次触摸时尝试解锁 iOS AudioContext；音效尚未准备好时跳过当次，不在玩家进入下一步之后补播。对 cursor、confirm、cancel、damage 做轻量前置静音检测和处理（最多扫描 280ms），避免原始音效里的开头静音造成“慢一拍”。没有修改音效的艺术内容。

右上角开关依旧同时控制 BGM 和 SFX，并立即停止当前正在发声的节点。浏览器缺少 AudioContext 时使用预加载的 HTML Audio 作为兼容回退。实际触屏响应速度仍受设备、浏览器与系统音频输出延迟影响。

## 开局确认、夜间固定轮次与两分钟限时（2026-10-31）

- **所有真人先抽牌：** 房主点击开始后，进入 `deal`（抽牌确认）阶段，六张身份牌只发往各自客户端；房主及其他真人均需翻开身份卡并点击“进入村庄”。房主使用 `dealReady` 按真实玩家 ID 记录确认状态，只有所有在线真人都确认，才进入第 1 夜。抽牌等待不设两分钟自动跳过，否则无法满足“每个人都看过自己的身份”的条件。离线者转为 AI 时不再等待其确认。
- **固定夜间公示：** 每一夜都按 **狼人 → 预言家 → 守卫** 的顺序显示公开提示，每轮约 4 秒，三轮总计至少 12 秒；即使预言家或守卫已经出局，提示仍完整播放，不把存活情况暴露在提示界面上。当前游戏没有女巫，不额外增加女巫角色或技能。夜间实际行动仍然私密、可在倒计时内提交；公示轮次只是统一的阶段提示，不通过客户端公开各职业是否行动。
- **统一倒计时：** 夜间、白天发言及投票阶段分别有**最长两分钟**，计时从该阶段开始（不是每个菜单点选都重新计时）。左下行动区显示剩余时间；各客户端根据房主同步的剩余毫秒数本地显示，但由房主统一执行超时与截止后的拒绝操作。所有所需行动提前完成，可提前进入下一阶段；夜间仍至少保留上述 12 秒的完整公开提示。
- **超时弃权：** 狼人、预言家、守卫如果没选择，视为当夜不使用对应技能；白天没发言的玩家自动视为“暂不表态”；没投票的玩家记录为弃票，不算给任何候选人的有效票。全体弃票则相当于平票，当日无人放逐。每一局获胜后计时停止，重开后不继承上一局的截止时间。
- **多人同步及语言：** `snapshot()` 仅提供每位玩家自己的秘密身份、所有真人的确认总数及相对剩余时间，新增显示文本已有 English / 简体中文 / 日本語。联机仍使用原 PeerJS 通道，不需要新增服务器。

程序逻辑所在：`startGame()` → `acknowledgeRole()` → `beginNight()`；时限由 `armPhaseTimer()` / `cancelPhaseTimer()` 管理，前端显示由 `updatePhaseHud()` 刷新。测试覆盖：双人身份确认门禁、固定 1/3 至 3/3 夜间提示、无响应跨阶段推进至最终结算、全员弃票不误杀、迟到投票拒绝。**尚未通过真实 iPhone / 多网络环境的完整计时验收。**

## 音量与真人玩家自定义头像（2026-10-31）

顶部齿轮 **Settings / 设置 / 設定** 可随时打开设置面板。**这里仅调整声音**：分别用 `bgmVolume` 和 `effectsVolume` 调整背景音乐与操作音效，范围 0–100。数值存储在各自浏览器的 `localStorage`，右上角原有的音乐开关仍可一键暂停或恢复全部声音。

**真人玩家的头像只能在开局前的首页选择。** 昵称输入框下方是 `home-avatar-picker`：从电脑硬盘或手机相册选择 PNG、JPEG、WebP（每张小于 8 MB），也可以直接使用随机预设头像。首页会立即显示所选头像预览；玩家确认后才点击 **Solo / Create room / Join room** 进入游戏。上传图片处理期间，三个进入游戏按钮暂时不可点击，避免未完成压缩就开始游戏。进入游戏后，头像不再通过音量设置更改。

客户端在本机将图片裁成方形，并压缩成小于约 26 KB 的 data URL，作为公开头像发送给同房间的其他玩家。用户上传图片保存在本人浏览器的 `moonlit-avatar` 中，联机时通过原有 PeerJS 连接共享；**没有额外的上传服务器**。请勿选用不愿展示给同房间其他人的私人照片。

不上传、或点击 **Random preset portrait / 随机预设头像**，就会随机选用六张学院肖像素材之一，首页预览与进入游戏后的头像一致。AI 人物也使用随机预设肖像，但**没有头像上传功能**。居民站位、中央发言框、投票目标卡共用同一张头像，并且不根据狼人身份或其他秘密角色决定头像。房主发起下一局时仍保留真人已选择的头像；玩家掉线被 AI 接管后，房间停止展示该真人上传的头像。

主要接口：`faceMarkup()`、`resizeAvatar()`、`applyOwnAvatar()`、`randomPortrait()`、`snapshot()`。头像只在首页选择并由创建/加入房间流程发送，音量可在游戏中随时调整。修改的只是公开外观状态；不修改胜负规则、隐藏身份、发言或投票处理。浏览器禁用本地存储时，选择可在当前页面运行，但刷新后不会保留。

## 多语言支持 / Localization (English · 简体中文 · 日本語)

游戏首次访问默认 **English**。顶栏左侧可以切换 **EN / 中文 / 日本語**；选择保存在浏览器 `localStorage` 的 `moonlit-language` 中。清空网站存储或首次在新浏览器打开时恢复英语默认值。设置只保存在本设备，不会修改好友的语言。

翻译词库位于 `moonlit-village/index.html` 的 `translations.en / translations.zh / translations.ja`，涉及首页、角色与能力、抽牌、昼夜动画、系统公告、发言、投票、结算、错误提示和可访问性标签；代码中的 `applyStaticLanguage()`、`render()`、`localizeLog()`、`localizeSpeech()` 以及 `updateLanguageOverlays()` 负责显示更新。用户自己输入的昵称不会自动翻译。

**多人模式兼容：** 房主仍以原有规范化的消息和角色 ID 传输游戏状态。客户端收到状态后自行翻译显示，不会因语言不同修改角色分配、AI 策略、投票或秘密身份。六名预设电脑玩家的名字可显示为本地化名称，但内部名字仍保持原来的唯一标识。若系统出现无法识别的新增公告，暂时回退原始消息以避免误译。

### 渲染与规则代码边界

当前全部页面位于单文件 `index.html` 中；游戏运行逻辑和展示仍然耦合，因此采用 **叠加视觉样式 + 独立 UI 辅助函数** 的改造方式，暂不搬动底层状态机。

- `render()`：主 UI，绘制房间信息、居民、身份、公告、行动菜单。
- `button()`：普通操作按钮 HTML。
- `rpgRenderMessages()`：公告与对话的单独渲染。
- `rpgActivateMenu()`、`rpgSelectTarget()`、`rpgHighlightTargets()`：光标菜单及居民选择。
- `showRoleDeal()`：现有开局抽身份牌视觉呈现。
- `handleTimeScene()`：现有昼夜场景的展示层动画。
- `startGame()`、`beginNight()`、`stepBots()`、`botNight()`、`finishNight()`、`botSpeech()`、`botVote()`、`finishVote()`、`winCheck()`、`accept()`、`snapshot()`：规则、玩家状态与 AI，第一阶段未修改。

### 在手机上验收

1. iPhone Safari 打开 [月下疑云](https://oskikaiti-sys.github.io/neon-mobile-arcade/moonlit-village/)，创建单人局。
2. 抽取身份牌，检查公告是否使用 RPG 对话窗口、系统消息是否居中。
3. 发言阶段检查四个纵向选项是否完整可点；点击「我怀疑某人」再点存活居民，确认上方选中状态与「确认选中的居民」。
4. 投票、下一夜和结算；滚动公告，确认旧消息没有消失。
5. 用桌面键盘测试上下箭头、回车和返回；在系统设置中开启减少动态效果，确认无打字机和闪烁。
6. 在两台设备中创建房间、加入、公开发言并核对同步。
